# Contributing

This course is free for everyone, and contributions help keep it accurate, clear and useful to more people. Thank you for taking the time.

## Ways to help

- **Report a mistake.** A wrong explanation, a broken link, a cell that fails, a check that accepts a wrong answer. [Open an issue](https://github.com/anupbagale/python-for-ai-ml/issues) with the module, notebook and cell, what you expected, and what happened.
- **Say what confused you.** If you had to read something three times, that's worth reporting even if you worked it out. Clearer explanations help the next person.
- **Suggest an exercise or project idea**, especially one based on real, openly licensed data.
- **Translate.** Translations make the course available to people who don't read English comfortably. Please open an issue first, so we can agree on a folder layout and avoid two people translating the same module.

## Principles every contribution should follow

These keep the course open to everyone:

1. **Free to run.** Everything must work in free Google Colab and on an ordinary laptop. No paid services, no API keys, no expensive hardware.
2. **Open data only**, with its source and licence stated in a `data/README.md`.
3. **Plain language.** Short sentences, everyday words, and every new term explained the first time it appears (and added to the [glossary](00-start-here/glossary.md)).
4. **Runnable and checked.** Notebooks must run top to bottom without errors. Exercise checks should catch common wrong answers, not just confirm correct ones.
5. **Honest results.** Report numbers as they come out. If a model doesn't beat a baseline, say so and explain why.
6. **Accessible charts.** Use the course's colour-blind-safe palette, give groups different marker shapes as well as colours, and explain every chart in the text.

## Making a change

1. Fork the repository and make your change on a new branch.
2. Run any notebook you changed from top to bottom (in Colab: Runtime, then Restart and run all) and save it with its outputs.
3. Open a pull request describing what you changed and why.

Small fixes like typos can go straight to a pull request. For anything bigger, open an issue first to discuss it.
